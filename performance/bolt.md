## 2024-03-05 - Optimize App renders due to localStorage side-effects
**Learning:** `App.tsx` has a subtle double-render cycle because `useRecentSearches` writes to localStorage via `useEffect`, which triggers a state update. This causes a cascade where heavy child components like `ResultsView` (containing Tabs, Framer Motion animations) are completely re-rendered even though their input `data` prop is completely identical.
**Action:** Always check the dependency graph of state updates triggered by side effects (like localStorage syncing). Use `React.memo` on heavy presentational components (`ResultsView`) receiving stable data, and `useCallback` on hook methods (`addSearch`) to prevent cascading reference changes. Use `vi.mock` with internal counters in a temporary `.perf.test.tsx` file to explicitly measure and prove the reduction in render cycles.
